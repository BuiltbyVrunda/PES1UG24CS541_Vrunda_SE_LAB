  2. How a click travels

  2. Pygame event: main.py:26-29 (main.py#L26-L29) reads each event and calls
     engine.handle_event(event). This is called once per event, so the event is
     not delivered twice.
  3. Click coordinates: game_engine.py:39-40 (game/game_engine.py#L39-L40)
     passes event.pos to _handle_click.
  4. Collision detection: each hole has a square hit-box, hit_size=150 in
     hole.py:4 (game/hole.py#L4), tested with collidepoint.
  5. Mole selection: the original loop checked all 9 holes and never stopped
     after the first match.
  6. Score update: score += 1 ran for every active hole under the click.

  3. Root cause

  The holes are 125 px apart horizontally and 120 px apart vertically, but each
  hit-box is 150 px wide. Neighbouring hit-boxes therefore overlap by 25 px
  horizontally and 30 px vertically. Because the loop never stopped at the first
  match, every active mole in that overlap scored.

  I reproduced it on the original code from git HEAD: a border click scored 2
  points, and a click where four boxes overlap scored 4.

  4. The fix

  The change is in _handle_click only, in game_engine.py:42-58
  (game/game_engine.py#L42-L58):
  - It collects the active holes whose hit-box contains the click.
  - It picks the one whose centre is closest to the click and whacks only that
    one.
  - If there are no candidates, it counts a miss.
  - On an exact tie, min() keeps the first hole in list order, so the result is
    deterministic.

  There is no special case for borders, and no new class or helper. I also
  replaced the two stale "deliberately overlapping, see Task 1" comments with
  accurate ones. There are no changes to the UI, file names, folders, hit_size

  The change in simple terms

  When you click, the game has to decide which mole you hit. The old code asked
  every hole "did the click land in your box?" and gave a point to every hole
  that said yes. The new code collects the holes that say yes, picks the single
  closest one, and gives one point for it.

  Original code

  def _handle_click(self, pos):
      hit_something = False

      for hole in self.holes:
          if hole.rect().collidepoint(pos):
              if hole.whack():
                  self.score += 1
                  hit_something = True

      if not hit_something:
          self.misses += 1

  Modified code

  def _handle_click(self, pos):
      candidates = [h for h in self.holes
                    if h.active and h.rect().collidepoint(pos)]

      if candidates:
          target = min(candidates,
                       key=lambda h: (h.center_x - pos[0]) ** 2 + (h.center_y -
  pos[1]) ** 2)
          target.whack()
          self.score += 1
      else:
          self.misses += 1
  I also updated the comments here and in game/hole.py to match. Nothing else
  changed.

  Why the original could score twice

  - Each hole's hit-box is a 150×150 square (hit_size=150).
  - The holes are only 125 px apart horizontally and 120 px apart vertically, so
    neighbouring boxes overlap. For holes 0 and 1 the overlap is x = 175
    to 200.
  - The for loop has no break or return, so it checks all 9 holes on every
    click.
  - If two neighbouring moles are up and the click lands in the overlap, both
    holes pass collidepoint and both whack() calls return True. score += 1
    therefore runs twice for one click. In the 4-way corner it ran four times.

  Why the new code gives at most one point

  - The score is increased in exactly one place, self.score += 1. It sits
    outside any loop and runs once per call.
  - min() returns a single hole, so only one mole is whacked. Two moles cannot
    both receive the same click, however many boxes overlap.
  - The choice is deterministic. The closest centre wins, and an exact tie goes
    to the earlier hole in self.holes (row by row, left to right).
  - Clicks with no active mole under them still count as a miss, and a click
    clearly inside one mole still hits that mole, so the rest of the behaviour
    is unchanged.
